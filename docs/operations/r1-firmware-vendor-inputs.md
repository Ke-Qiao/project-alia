# R1 通用板端应用所需资料（商家沟通草稿）

更新：2026-10-21。用户已暂缓 R1 固件改造，本文仅保留为将来明确恢复时的资料请求草稿，尚未发送给商家；当前不继续索取资料。

目标是在 R329 上开发适合 Alia 的通用音频前端应用：优先用 Rust 替换板端 `vtn_example`，复用现有 BSP、驱动和成熟音频引擎，使处理后 PCM 的持续输出与固定唤醒词解耦。无需先重写 DSP，也不要求交付全部算法源码。R1 模块本身不列为故障；此前 A 方向声音小是 `beam=5` 对非目标方向的正常抑制，AEC 事项仍由用户另行与商家确认。

## 已有依据

- 实测固件为 `UART_REAL, circle6:1.9.6.f8ef651@master engine:circle6.1004`，构建时间为 `Sep 3 2026 22:40:02`。
- 新资料包包含 `v1.9.1_real_uart.img`、`v1.9.3_real_uart.img`。对 **1.9.3 镜像**的静态解包发现 `/etc/init.d/vtn_example`、`/usr/lib/libvtn.so`、`/lib/firmware/dsp0.bin`、`dsp1.bin`，以及 glibc 2.23 根文件系统；这不等于确认当前 1.9.6 内部完全相同。
- 随后补查嵌套的旧资料，另有 `v1.5.img`；其 `libvtn.so`、`vtn.ini` 和 `cae_init_param.ini` 与 1.9.3 镜像提取件逐字节相同，仍没有板端头文件。该包内应用的版本字符串为 `circle6:v1.3.0`，仅凭镜像文件名不能确认运行版本或当前设备兼容性。
- `vtn_example` 引用 `vtn_api_init`、`vtn_api_interact`、`vtn_api_destroy`；`libvtn.so` 还导出 `vtn_api_get_version`。目前只有二进制符号，缺少可据以编写正确 Rust FFI 的函数声明、结构体和回调约定。
- 公开串口支持版本查询、`manual_wakeup` 波束选择和单个自定义中文唤醒词；尚未找到受支持的“冷启动后无需关键词即可持续输出处理后 UAC”说明。命令成功 ACK 不能证明该模式已成立。

## 最小资料请求

| 所需资料 | 具体内容与用途 |
| --- | --- |
| 当前版本恢复包 | 对应上述 **1.9.6.f8ef651** 和本机板卡版本的完整恢复 IMG、校验值、适用硬件 revision，以及失败后恢复步骤。1.9.1/1.9.3 不能直接视为等价恢复包。 |
| 可替换板端应用的构建路径 | 板卡 revision 与目标 ABI；匹配的交叉编译工具链、sysroot、链接参数；`vtn_example` 原 userspace 工程或等价最小 SDK 示例；替换应用、启动配置、打包 IMG 的实际命令。优先只重建 userspace；如果必须重建 BSP，请提供对应版本及必要板级配置。 |
| `libvtn` 的真实接口 | 与该版本库匹配的 C 头文件：上述四个 API 的完整签名、结构体布局、枚举/命令编号和返回码；初始化/销毁顺序、回调所在线程、可否重入、线程安全、音频缓冲区 ownership/生命周期、长度单位及对齐要求。不能以导出符号名代替接口定义。 |
| 无 KWS 的处理后 PCM 路径 | 一个可运行的最小示例或受支持配置：冷启动后显式启用采集，不说唤醒词、不周期性伪造唤醒，持续取得处理后 16 kHz/PCM16/单声道音频并送到 UAC；说明禁用 KWS 后前端和输出回调是否仍运行、静默后的行为、启动/停止和状态读回方式。若需另一接口或回调，请提供其声明与数据格式。 |
| 匹配的引擎资源和板级配置 | 与库匹配的 `circle6.1004` 资源、DSP 固件、麦克风/参考通道映射、已有 calibration/初始化配置及其版本对应关系；明确哪些配置必须保留、哪些允许应用修改。请求旨在保持已有效的音频处理，不开展新的 AEC 根因诊断。 |

同时请提供 SDK 的修改/链接说明与后续分发条件。

如果现有 1.9.6 已有受支持的常开 processed UAC 模式，请优先提供该模式的正式配置、版本适用范围和状态语义；如果有可定制板端应用 SDK，也可以直接复用。上述任一方案若完整满足持续音频与可选唤醒的需求，就不必重写 DSP 或重建整个系统。
