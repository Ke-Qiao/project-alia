Alia 的边界已核对：[SpeechPipeline](../../packages/alia-embedded/src/module/speech/duplex.rs)在 PCM 检测到唤醒时建立会话，`EventBus` 上的唤醒通知本身不会建会话；capture 缺口会结束会话、清空预卷并要求新唤醒。先完成持续处理音频可复用该路径，无须为摆脱固定词立即建设第二套板端唤醒系统。若后续保留可选板端 KWS，再接入同一个会话拥有者与新鲜度判断，不能伪造 PCM、角度或置信度。

方位如需向 Agent 提供，走现有 Embodiment 传感器与时效契约；Agent 发起的设备配置操作走 Execution 和受信设备能力。音频采集与会话仍归 Embedded 音频路径，expression 仍只生成候选表达，无串口／设备写入权限。

本版不要求六路原始音频、新的板端自定义 KWS 模型、连续声源跟踪、ROS、OTA 或通用驱动框架。AEC 诊断与调参待用户和商家确认，不作为本轮固件通用化的附加修复。离线验收应覆盖协议非法输入、模式切换、重复／迟到 ACK、断线与重启，并分别记录主机测试、板端目标构建与未执行的烧录／实机验证；本轮不重复已有硬件录音。
