## 最小只读核对

拿到可信目标后，只在该目标上采集下列信息。命令均为待执行清单；本轮未运行 SSH，也未打开音频或串口设备。保留命令退出码、时间、主机身份与源码提交，失败项写明 missing/denied，不自动安装软件或提权。

| 项目 | 在确认目标上的只读命令/资料 | 用途 |
| --- | --- | --- |
| Pi 系统与资源 | `uname -a`、`cat /etc/os-release`、`getconf LONG_BIT`、`free -h`、`df -h` | 锁定系统、架构、RAM、磁盘；供电/散热型号仍需现场资料 |
| ALSA 枚举 | `cat /proc/asound/cards`、`arecord -l`、`aplay -l`、`arecord -L`、`aplay -L` | 核对卡和 PCM；枚举不证明实际可用格式或声学质量 |
| USB 与串口身份 | `lsusb`、`ls -l /dev/serial/by-id /dev/serial/by-path` | 稳定设备标识；缺失目录不是失败部署的充分证据 |
| 构建环境 | `rustc -Vv`、`cargo -V`、`protoc --version` | 与仓库锁定依赖和实际构建产物对应 |
| 部署目录 | 确定账户后逐个核对目标目录 owner/mode、可写范围和挂载文件系统 | Settings/setup 信任同机操作者，Host/Origin 不替代账户权限 |
| 服务身份 | 确认端点后读取已有 `/health` 和 Easy-Turn `/v1/capabilities` | 记录实际版本/能力；保持 Server `probe=false`，不自动启用外部付费探测 |

不使用 `arecord`/`aplay` 的录放音模式、`i2cdetect`、串口 open、MCU reset 或写寄存器来补充枚举信息。电气参数、GPIO、供电和安全姿态只从对应型号资料与现场确认取得。

## R02 首个交付包：声学链路与 AEC

复用 [native reference/clock 契约](../refactor/audio-reference-clock-design.md)和现有 post-mix reference。mixer 已经存在，AEC consumer 尚不存在。先固定 H02/H03，明确是否已有硬件 AEC，再决定软件 AEC 的位置、具体实现和依赖；不预先叠加未知处理器。

1. 将真实 capture 与 render reference 的 boot/stream、continuity、sequence、lost counters、格式、游标、clock quality、可用 queue delay 与主机观察时间纳入同一测量记录。现有 AudioDebugRecorder 不提供这一同步证据，默认不启用录音。实际音频的保留位置、时长与删除规则需在采集前确定。
2. 单一音频 worker 消费 reference，在 wake/VAD/上传之前处理 capture。按选定 AEC 的要求重分帧，不能把现有 1024 样本参考块或上传帧当作 AEC 帧。明确两设备时钟漂移、参考缺口、xrun/重开与 reset/重新收敛；缺失参考不能补成“真实静音”。
3. 使用确认的设备和素材做单讲、双讲、附和、明确 WAIT/Continue、噪声、重连与尾音测量；保留样本量和失败分母、用户语音完整性、自唤醒/自转写、插话到实际停声时间、资源趋势。验收阈值在基线测量后明确，模型标签和服务耗时不能代替听感或停声证据。

无硬件时先做接口和已有离线回归核对；不把当前软件 reference 测试勾选为 AEC 已完成。

## R03 首个交付包：资产身份与反馈协议

复用 [Body 契约](../refactor/body-command-design.md)、[动作资产](../../packages/alia-embedded/docs/motion-assets.md)及现有唯一 writer。命令签名目前只覆盖动作文件名和参数，未覆盖资产 bytes；UART flush/I²C write 只能证明主机提交。

1. 确定动作资产的审核者、签名/可信摘要分发方式和版本。将资产内容身份纳入受认证意图；对同一次有界读取取得的 bytes 校验并解析，避免校验后重开读取另一份内容。缺失、不匹配、同名替换、旧版本及文件变更必须在 native 准入前失败。该软件子包不依赖舵机性能，但不能把旧资产标为安全或让模型自报摘要成为信任根。
2. 固定 H04 后定义控制板 boot、命令标识、ACK、实际位置/速度、限位与停止反馈；明确断连状态和是否支持读取实际状态。没有反馈能力就保持 unknown，不能将软件退休、MCU 接纳或网络 ACK 报成物理到位。
3. 先复用 mock 故障测试，再在确认限位、供电和停止策略的现场低风险条件下验收迟到命令、断连/重启、限位、停止失败与恢复。未知结果先核对原命令，不盲目重发。

## 进入 R05 的条件

- [ ] H01—H05 已填实际值，设备/模型/代码版本与部署配置身份固定，密钥由现有受控方式保存。
- [ ] R02 有选定音频链、AEC/双讲/尾音与端到端暂停恢复证据。
- [ ] R03 有资产内容身份、控制板 boot/ACK/反馈、机构限位及停止/恢复证据。
- [ ] 从独立干净目录和数据库完成安装、配对、启停、升级/恢复；沿用 [无前端操作](server-embedded.md)，不覆盖开发者现有配置或数据库。
- [ ] 对本轮 Settings 审计记录的慢模型与并发设置等待，给出并验证操作恢复和关闭上界；不能把单项 SQL 的 2 秒期限当作整请求期限。
- [ ] 准备至少 24 小时混合负载、断网、进程退出、设备重连与资源上界测试，保留完整失败和资源关闭记录。未实际运行不得勾选。

R05 的前置准备可以与 R02/R03 并行，整机通过必须在前述条件满足后报告。当前六轮仍为 R01/R04 完成，即 **2/6**；不是项目完成百分比。
