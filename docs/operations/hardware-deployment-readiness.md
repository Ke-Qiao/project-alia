### 2026-10-14 实际只读盘点

完整证据见 [本轮交接](../refactor/handoffs/2026-10-14-hardware-confirmation/README.md)。首次绕过 SSH config 的默认身份登录失败；沿用本机已配置身份后成功，保持严格已知 host key 验证，没有接受新 key 或写入凭据。

- 根文件系统约 117 GiB、可用约 104 GiB；单次温度 36.4℃。它们是盘点时的快照，不是负载或长期稳定性结果。
- `lsusb` 当前只有 USB root hubs，未识别 R1；内核列出两个 HDMI 音频设备。本用户对现有 `/dev/snd` 的 `root:audio`、0660 节点没有读写权限，所以 `arecord/aplay -l` 的无声卡提示不能解释成内核完全没有声卡。用户随后确认 R1 尚未接入，后续使用 USB，当前未枚举符合现状；不是接入后的识别故障。未更改组权限或打开 PCM 录放音；固件和格式仍待实际设备核对。
- `rustc/cargo/protoc` 在本次非交互 PATH 中未找到；进一步只读确认 `~/.cargo/bin` 已有 Rust shims，rustup 列出 active/default `stable-aarch64-unknown-linux-gnu`。这不是“Rust 未安装”；后续部署需固定实际版本及调用环境，`protoc` 可用性仍待解决。
- 存在 `/dev/i2c-1`、`/dev/i2c-13`、`/dev/i2c-14`，没有扫描总线或读写寄存器；节点存在不证明 PCA9685 板卡在线。没有 USB 串口稳定标识目录，不能据此推断 I²C 板卡缺失。

## 最小只读核对

目标已由用户指定，完成 host key 信任核对后，只在该目标上采集下列信息。下列命令是核对清单；是否已执行以本轮验证记录的实际结果为准，本文不将清单视为执行成功。保留命令退出码、时间、主机身份与源码提交，失败项写明 missing/denied，不自动安装软件或提权，不通过 PCM 录放音或串口 open 来完成枚举；ALSA 列举可尝试访问控制节点，不等同完全没有设备节点访问。

| 项目 | 在确认目标上的只读命令/资料 | 用途 |
| --- | --- | --- |
| Pi 系统与资源 | `uname -a`、`cat /etc/os-release`、`getconf LONG_BIT`、`free -h`、`df -h` | 锁定系统、架构、RAM、磁盘；供电/散热型号仍需现场资料 |
| ALSA 枚举 | `cat /proc/asound/cards`、`arecord -l`、`aplay -l`、`arecord -L`、`aplay -L` | 核对卡和 PCM；枚举不证明实际可用格式或声学质量 |
| USB 与串口身份 | `lsusb`、`ls -l /dev/serial/by-id /dev/serial/by-path` | 稳定设备标识；缺失目录不是失败部署的充分证据 |
| 构建环境 | `rustc -Vv`、`cargo -V`、`protoc --version` | 与仓库锁定依赖和实际构建产物对应 |

| 服务身份 | 确认端点后读取已有 `/health` 和 Easy-Turn `/v1/capabilities` | 记录实际版本/能力；保持 Server `probe=false`，不自动启用外部付费探测 |

不使用 `arecord`/`aplay` 的录放音模式、`i2cdetect`、串口 open、MCU reset 或写寄存器来补充枚举信息。电气参数、GPIO、供电和安全姿态只从对应型号资料与现场确认取得。

## R02 首个交付包：声学链路与 AEC

复用 [native reference/clock 契约](../refactor/audio-reference-clock-design.md)和现有 post-mix reference。mixer 已经存在，生产软件 AEC consumer 尚不存在。用户已说明 R1 支持硬件 AEC，因此先核对所选阵列的实际工作模式、输出声道和播放参考要求，再决定是否需要软件 AEC、放置位置与依赖；不在未知硬件处理之后直接叠加另一个消回声处理器。

“支持硬件 AEC”不等于已开启，更不等于 Pi 的扬声器信号已进入阵列的回声参考路径。麦克风和扬声器位于同一 Pi 也不能证明参考已连接或采播共享时钟。当前 post-mix 软件参考只证明主机音频边界，不证明阵列已经消费它。参考路由、接线与配置需依据该型号资料和现场核对；扬声器/功放未选定前不固定电气接法或声学阈值。

已从 [亚博 R1 官方介绍](https://www.yahboom.com/build.html?id=16444&cid=743) 核对：UAC 采集输出与功放输出参考接口是不同路径，不能默认把 USB 播放当作 AEC 参考。具体版本、输入额定值与功放兼容性未确认；条件性扬声器/功放方案见 [audio HANDOFF](../refactor/handoffs/2026-10-14-hardware-confirmation/audio-HANDOFF.md)。

1. **R02-A 软件证据包已完成**，源码 `e557ceb`，见 [10/10 checklist](../refactor/checklists/r02-a-2026-10-14.md)。native capture 与最终 playback reference 的 boot/stream、continuity、sequence、lost counters、格式、游标、clock quality、可用 queue delay 与主机观察时间已纳入同一有界格式；采播仍各自独立时钟。旧 AudioDebugRecorder 已删除，默认没有自动证据会话或文件录音；运行采集时仍有固定大小的内存 PCM 队列。真实音频的保留位置、时长与删除规则需在采集前确定，本轮没有采集真实音频。
2. 独占 reader、有界导出与合成 PCM 离线重放已完成，macOS 默认 Embedded 回归284/0/0；本轮Linux/ALSA未运行。未来若采用软件 AEC，由同一音频 worker 安排参考消费，并在 wake/VAD/上传之前处理 capture；按选定 AEC 的要求重分帧，不能把现有 1024 样本参考块或上传帧当作 AEC 帧。若使用阵列硬件 AEC，则记录其实际处理输出与参考来源，不把软件旁路命名成软件 AEC。两种路径均须明确时钟域、参考缺口、xrun/重开与重新收敛；缺失参考不能补成“真实静音”。
3. 使用确认的设备和素材做单讲、双讲、附和、明确 WAIT/Continue、噪声、重连与尾音测量；保留样本量和失败分母、用户语音完整性、自唤醒/自转写、插话到实际停声时间、资源趋势。验收阈值在基线测量后明确，模型标签和服务耗时不能代替听感或停声证据。

设备尚未完成当前核验；已完成的有界记录格式、离线重放和回归不能代替现场核验，不把软件 reference 测试或 R1 型号说明勾选为 AEC 已完成。当前软件继续推进下述 R03-A，现场资料确认后再开展真实 R02/R03 验收。

## R03 顺序：先保持与初始化，再资产身份及反馈

复用 [Body 契约](../refactor/body-command-design.md)、[动作资产](../../packages/alia-embedded/docs/motion-assets.md)及现有唯一 writer。命令签名目前只覆盖动作文件名和参数，未覆盖资产 bytes；UART flush/I²C write 只能证明主机提交。

**R03-0 软件修复已完成，真实硬件仍禁用。** 源码 `b5100d7` 已删除停止 reset 和旧 soft-start 配置；`calibration_confirmed=false` 为默认，未确认的 mock 无启动输出/动作准入，native 配置未确认则拒绝。确认后仍验证矩阵与中心限制，只完整提交一次中心目标后建立软件 previous；初始实姿态未知，不能据此宣称物理限速归中。PCA 初始化已开启 AI，并由原 owner 对取消/失败/短写执行必要恢复；多板构造未提交时逆序恢复此前板，恢复失败保留 unknown。实际恢复只证明主机事务提交，仍需现场证据。

R03-0 当轮 macOS 默认 Embedded 回归263/0/0，详见 [R03-0 交接](../refactor/handoffs/2026-10-14-r03-0/README.md)；后续 R02-A 同一回归已达284/0/0，仍覆盖PCA14项。Linux daemon停止，两轮均未运行当前Linux。用户尚无校准资料，不应把确认开关设true来绕过该前置。停止/断连保持的物理结果、供电/OE和实际限位仍未验收。R02-A软件已完成，接下来推进下述R03-A资产内容认证。

1. 确定动作资产的审核者、签名/可信摘要分发方式和版本。将资产内容身份纳入受认证意图；对同一次有界读取取得的 bytes 校验并解析，避免校验后重开读取另一份内容。缺失、不匹配、同名替换、旧版本及文件变更必须在 native 准入前失败。该软件子包不依赖舵机性能，但不能把旧资产标为安全或让模型自报摘要成为信任根。
2. 当前器件为 PCA9685A + MG996R；先核对该组合与现有 PCA9685 后端的实际接口和可观测能力。当前后端只有 I²C 写入，没有控制板 boot/ACK 或位置读回；不能为所选硬件虚构 MCU 协议。命令标识、实际位置/速度、限位与停止反馈只按确有的能力接入，没有反馈就保持 unknown，不能将软件退休、主机写入或网络 ACK 报成物理到位。幻尔总线方案留待后续指定具体器件和协议后处理，本轮不实现适配。
3. 用户已选择停止/断连时保持，后续实现与验证不得擅自改成归零或卸力。需明确保持的是最后设定目标/输出，还是可测量的机械位置，以及持续供电、Pi/控制板重启和掉电时的行为；“已发保持命令”不证明机构保持。机构负载、供电、限位与校准尚缺，先复用 mock 故障测试，再在现场条件明确后验收迟到命令、断连/重启、限位、停止失败与恢复。未知结果先核对原命令，不盲目重发。
