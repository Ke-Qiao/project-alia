# 插件契约与信任边界

更新：2026-10-17；核对基线`89d04a2`，应用源码仍为`6c62c84`。本页是目标契约及实施分界，**不声明当前运行时已经满足目标**。本轮不修改运行API、权限或协议，不安装依赖、不运行插件／模型／设备。默认shadow、当前政策、Execution批准、Context来源／隐私校验、Delivery/Body身份与取消保持；R03暂停。

## 1. 目标与决策状态

用户明确要求：**允许安装未经审查的第三方代码，作为后续必须保留的扩展目标**。人工源码审核、官方市场认证或发布者签名不能成为所有安装的硬性前提；未经审核、未签名和未识别发布者均有独立记录。安装、能力授权、启用和每次业务效果批准相互独立。

| 决策 | 状态 | 推荐契约，确认后定稿 |
| --- | --- | --- |
| D01 管理主体 | 待用户答复 | 管理员负责部署／授权及跨用户数据管理；普通用户只使用获授权能力及隔离后的本人数据入口 |
| D02 未审核代码运行方式 | 待用户答复 | 安装后默认不运行；默认隔离执行，后端不能满足约束则拒绝；另保留必须明确授予宿主信任的受信本机模式，绝不自动降级 |
| D03 升级与撤权 | 待用户答复 | 升级先封闭新调用，原期限内排空旧调用后切换；停用／撤权取消并清理；新版本不继承旧执行批准 |

当前机制没有完整不可信代码隔离。文档的目标规则不能代替实现、动态负例和运行平台验证；后续未实现的能力必须报告不支持，不能借旧入口绕过。

## 2. 扩展分类与不可替换核心

| 类型 | 当前能力 | 目标边界 |
| --- | --- | --- |
| 受信编译期扩展／Provider | Rust trait、Bootstrap注册、编译feature选择；工具经Execution | 随应用发布；与宿主处于同一信任域。不能对任意同进程Rust代码声称安全隔离 |
| 外部工具／服务 | 既有服务adapter，尚无通用MCP host | 通过既有Execution入口和未来MCP／正式API适配接入；远端身份、凭据、工具目录和效果语义分别核对 |
| 本地进程扩展 | Server表达JSON子进程；Embedded包管理和JSON命令／事件 | 现实现按受信宿主代码理解；未来按明确执行模式运行，实例owner和输入输出协议受控 |
| 未经审查代码 | 当前无满足该信任域的运行后端 | 支持安装为未激活资产；后续提供经验证的隔离执行及受限宿主能力，不要求先将代码标成受信 |
| Skills／资源包 | 现有目录内容身份、索引发布和工具可见性 | 属于不可信内容／能力说明，不是代码执行授权；不得用Skill内容安装、启动或授权程序 |

Interaction、Context、Memory、Execution、Delivery、Companion与Platform的规范数据及最终政策归核心所有。插件可提交候选／事件／结果，由核心校验后采纳；不能接管SQL、替换核心registry、提交已批准的账本结果、任意读取完整记忆，或自行建立播放／Body权限。表达安全插件之后仍执行不可替换的内建校验。

这些是扩展接口和隔离宿主接口的边界；受信同进程／本机代码实际拥有宿主权限，其违规风险由代码信任与部署控制承担，不能宣称上述规则对恶意受信代码构成强制隔离。

Rust features只决定编译进哪些受信实现，不提供运行时安装、授权或沙箱。第三方支持不要求把所有扩展放入同一运行时，也不要求当前新增WASM、容器调度器或动态库ABI。

## 3. 五项独立信任事实

1. **来源**：发布者／来源地址／用户导入方式及验证结果。未审核、签名未知、签名无效是不同状态；在声明受验证来源的安装流程中，签名或受保护元数据验证失败必须拒绝，不得自动降格成未签名成功。用户明确选择的未验证本地导入可独立存在，但不能继承原发布者身份或信任。
2. **内容身份**：实际包、manifest、入口及锁定运行环境的身份。摘要由宿主对接收到的字节计算，插件自报摘要不是信任根；版本字符串不是内容身份。
3. **能力授予**：管理员或授权主体对具体版本、调用主体、资源、用途及额度的授予。manifest只请求能力，不能给自己授权。
4. **执行隔离**：被实际选择并验证的运行后端及有效限制。隔离能力不支持时保持已安装但不可运行；不存在静默切回普通子进程的路径。
5. **业务批准**：每次工具副作用仍受当前身份、Context／隐私、风险、Execution批准与预算约束。安装、启用、签名、能力授予和模型tool calling都不能替代它。

受信本机模式的宿主信任必须与一般启用授权分开呈现、持久记录并绑定内容身份。此模式意味着代码可能使用宿主账户权限；应用内代理不能约束恶意同用户代码，不能给它套用未审核隔离模式的保证。增加版本或切换模式不得自动扩大信任。

## 4. 管理面、调用面与数据权限

以下管理矩阵依D01定稿；现有REST/gRPC在后续实施前不具备这张表的全部保证。

| 操作 | 管理员 | 普通用户／插件 |
| --- | --- | --- |
| 安装、启用、停用、升级、回退、卸载、能力授予 | 当前身份复验后允许，保留审计与操作ID | 不可自行执行；模型或Skill不能代为提升权限 |
| 管理目录与使用目录 | 可见所管安装的版本、有效授权及诊断状态 | 只暴露当前可用工具的必要说明，不泄露宿主路径、凭据或其他用户数据 |
| 全局／跨用户插件用量、导出、清理 | 明确管理作用域；等待后及提交前复验 | 不能复用全插件导出／清理接口 |
| 使用已安装插件工具 | 仍需原业务批准与数据政策 | 仅对当前用户可见／可用的工具提出调用 |
| 本人数据导出／删除 | 按现有管理与隐私政策 | 经明确的用户隔离入口；用户ID由服务端身份派生，不能由插件自填 |
| channel／conversation数据 | 核对当前所有权与成员权限 | scope必须由可信调用上下文导出；不能只相信传入owner_id |
| 跨插件存储或注册工具 | 由受信核心管理 | 未审核host接口只允许自身namespace和获授资源；不交出raw DB或可操作所有owner的ToolRegistry |

设备管理的绑定control token仅证明已绑定控制方，不自动等价于某个人类管理员授权。未来Server到Embedded管理请求应绑定当前管理员、目标device/boot、操作、内容及管理授权版本；Embedded仍检查当前绑定和本地授予。具体wire格式后续双方一起实施，本轮不新增万能管理token。

读取敏感数据前、等待锁／队列后、提交副作用前须重新检查当前身份与授权版本。长期事件流绑定授权，撤销或断连时关闭准入并清理owner。管理员权力不等于允许把完整设置／密钥送入插件。

现有PluginStorage的namespace、collection、scope、schema、CAS、TTL和卸载保留规则继续复用。默认`retain_on_uninstall`保持；`delete_on_uninstall`与`export_required`仍按既有规则执行，删除本身需合法管理操作。更新manifest不能静默改为删除既有数据或跨owner导出。总量／单条限额由宿主限制，插件声明不能提高宿主上限；当前是否已实现见第10节。

## 5. 身份、版本与兼容

| 身份 | 内容与用途 |
| --- | --- |
| 扩展身份 | 宿主控制的稳定namespace／安装身份；保留来源关联，防止冒充builtin或接管另一个安装。显示名不能独自作为安全主键 |
| 资产身份 | 包字节SHA-256、字节数、manifest／入口关联及版本标签；安装读取、校验、解包与激活引用同一已验证资产 |
| 部署实现身份 | 资产身份、ABI版本、实际入口、锁定解释器／依赖环境修订或隔离镜像内容身份；不能只pin一个会动态加载任意依赖的脚本 |
| 授权身份 | 授权主体、扩展／资产、隔离模式、允许能力与资源scope、policy/grant修订；授予来源在宿主，插件无法自签 |
| 运行实例 | device／host boot或Server实例身份、唯一run/epoch及部署实现身份；同名重启必为新实例 |
| 调用／效果身份 | 稳定逻辑command／EffectRun ID、调用主体与scope、规范参数摘要、绑定运行实例；状态查询／取消沿用原身份 |
| 目录／协议身份 | 工具定义与注册修订、实现digest、ABI/协议协商版本及必要能力；声明、协议可用和权限获授分别验证 |

现有Execution的build／registration／implementation digest和批准绑定不替换为第二套账本；新增资产／实例事实应接到原规范身份。相同版本号而不同字节是新资产，旧批准不能复用；同包但运行环境、授予或工具schema改变，也不能假设旧批准有效。已执行的历史结果继续按原身份读取，不因升级抹去或伪造效果事实。

升级或回退均是显式管理操作。回退不是重启旧批准，不能绕过撤销、降低宿主政策或盲目回退数据库schema。实际版本范围和协议字段在实施时固定；缺少必要身份的legacy客户端不能静默获得新版执行权限。删除protobuf字段保留编号，调用者、两端生成物及契约测试一起更新；本轮不创建空proto／SDK占位。

## 6. 安装与发布

目标顺序：有界接收 → 私有暂存 → 静态检查 → 同资产身份记录 → 原子发布为未激活 → 单独授权与启用。安装过程不执行entry、安装钩子、包脚本或自动拉取依赖；未知发布者仍可进入未激活状态。若格式或目标运行后端不支持，明确记录原因，不改用不受限进程启动。

名称／目标路径、manifest与请求名称／版本一致性、入口归属、重复成员、符号链接／硬链接／特殊文件、解压后总量／文件数／单文件大小和权限均在宿主检查。解压及发布不得逃逸受控根，不能只靠字符串前缀；拒绝的成员类型先明确列入支持格式。包不能覆盖配置、key、授权记录或其他安装。失败只清理本操作拥有的暂存资产，已安装版本保持可辨认；不得原地半覆盖活动版本。

发布响应区分未发布、已发布、持久性未确认。沿用已有配置发布经验：已发布后同步失败不能假装文件没发布，也不能随意覆盖恢复状态；按操作ID和资产身份核对后受约束恢复。数值上限及文件系统实现以当前平台已有预算为起点，在实施前固定，不能让manifest或重试放宽。

解包／文件同步等blocking工作保留原完成句柄；取消调用者不会中止原生工作。只有观察原工作退出，才能删除其暂存目录或复用发布目标。验证与激活绑定同一不可变资产，不能先校验一个路径，再无条件执行后来被替换的内容。

## 7. 生命周期与取消

安装状态、运行状态、效果状态、资源清理状态分别记录。例如包已安装不等于运行ready；业务失败或unknown不等于进程已退出。

| 阶段／操作 | 目标契约 |
| --- | --- |
| Start／Starting | 验证当前管理授权、资产、隔离能力、数据与预算；取得唯一实例owner。spawn成功仅表示进程创建，不表示ABI ready |
| Ready／Running | 完成版本／能力握手后才接收调用；实际有效能力是请求、授予、后端约束和当前政策的交集 |
| Upgrade／Draining | 依D03：关闭新调用准入，已进入调用保留旧实例与原期限；待真实清理后激活新版本，不为升级延长期限 |
| Disable／Revoke | 关闭准入、使新使用权限立即失效，取消相关调用并保留原owner等待清理；禁止新的内容采纳和副作用。已dispatch效果的迟到真实回执、失败及清理事实仍按原身份入账，必要时保持unknown；保存事实不恢复授权 |
| Stop | 停止与完成回执分开；发signal不是退出证明，原child、管道任务和属于本次的后代／隔离实例须收口 |
| Cleanup pending | 原预算耗尽则报告未完成并保留owner／资产引用；不得标Stopped、删除包或用同一实例身份再启动，稍后可继续清理 |
| Uninstall | 先撤下发现／新调用，再停止并排空原owner，最后按数据保留规则和引用核对删除资产；不删除审计／历史EffectRun |
| Host crash／Restart | 新boot生成新实例身份；原运行结果可为unknown，先核对原资源和效果，不能仅凭同名包重放副作用 |

旧wait/output任务只能修改与自身instance一致的条目，不能按名字覆盖新实例。caller断开、timeout或async future丢弃不等于native工作／子进程结束。清理沿用现有期限与失败语义，不增加隐藏等待、无限排空成功条件或缩减测试并发。

## 8. 命令、事件与结果

明确区分`sent`、`accepted`、`running`、`completed`、`cancelled`、`failed`、`unknown`、`rejected`。这些是目标语义，不是在当前protobuf里已有的保证。子进程自报completed只证明它报告完成；需要外部事实的效果仍由对应适配器核验，物理到位／实际播放必须有原Body／Playback证据。

同一个逻辑请求重试沿用command ID及参数摘要；重复ID不同payload拒绝。观察和取消绑定原运行实例，迟到结果不得写入新实例／新会话。经过可能产生副作用的边界后，丢ACK保留unknown并观察原调用；不能生成新UUID重发。取消只能表示停止后续工作或请求取消，不能声称撤销已发生的外部效果。

stdin/stdout/stderr、请求体、单行／单消息、累计输出、并发、队列和订阅者都有宿主上限；在读入过程中限制，不能等完整收集后才截断。日志按UTF-8边界处理、默认不包含私有内容／密钥／原始stderr。慢消费者、非法帧、部分消息、事件序列缺口和broadcast lag明确报告，保留取消入口及原owner清理；流关闭不能被解释为所有事件均已送达。

## 9. 未审核代码的后续接入目标

后续必须交付可安装、可隔离运行的未审核示例，而不仅有文档中的未来字段。支持面按运行后端声明：WASM适合受限host调用，通用Python／native程序需要经验证的进程／容器／虚拟化隔离；本轮不选择或安装后端，也不承诺一个后端兼容所有语言和平台。当前Mac Server与Pi Embedded仍是范围，其他平台不自动扩张。

未审核执行默认不能访问宿主HOME、配置、密钥、数据库、设备、任意网络、进程创建、Docker socket或管理IPC。包只读，临时目录和自身数据namespace按授权提供；即使允许容器也不挂载宿主控制socket或使用privileged作为默认。CPU／内存／输出／时间限额必须由实际后端执行，不支持的限额不能用manifest字段冒充。

宿主能力通过经过身份和scope校验的代理提供。private Context/Appraisal只提供本次获准且最小化的输入，拒绝直接序列化全部ExpressionInput／materialized memory；结果仍是候选，重新经过来源与政策校验。Appraisal实现pin及SQL批准保持，插件安装身份不能直接充当解释器批准。敏感日志、缓存和导出也受原撤销／保留规则约束。

效果类网络／工具／设备调用走Execution或对应规范Delivery/Body入口；插件不能拿宿主凭据后自由绕行。需要普通网络访问的插件必须明确范围和风险：对任意获授网络或文件访问，无法承诺其全部副作用都由Alia账本观察，不能把任意网络授权宣传成严格效果代理。首先提供明确的代理能力；扩大直连能力须另行验收且不改变现有业务批准。

私有输入与外发能力的组合需要单独核对用途和当前数据政策，不能因为两项能力各自获准就默认允许将私有数据发送出去。撤权阻止后续读取／调用，不能召回已经交给外部代码或远端的数据；这一边界须在授予与审计中可见。

本地stdio MCP也是执行代码，必须进入同一安装／授权／隔离模型；远端MCP则绑定可信连接配置、凭据受众和工具目录身份。工具注解、描述、返回内容、URI和资源请求不能授予权限或提升为系统指令。外部服务自身的执行不可被本机sandbox证明，需要明确结果可信度和unknown语义。

| JSON Appraisal无provenance pin，示例raw trace与正式门槛不一致 | 内容身份接原批准链，最小私有输入 | Appraisal/Context、示例、批准／篡改／撤销拒绝回归 |
| 存储已有单条上限／scope声明／TTL／CAS／retention | 这些不等于不可信caller隔离或插件总配额 | scoped host API、跨owner拒绝、累计quota、卸载保留与导出条件 |

具体源码位置与已有测试见[三份分工和Root交接](../refactor/handoffs/2026-10-17-plugin-contract/README.md)。当前没有通用MCP／隔离后端或独立第三方SDK交付证据；旧noop生命周期为空插件目录，不代表插件进程矩阵通过。

## 12. 行业资料依据与项目选择

以下官方资料于2026-10-17核对，仅作设计依据；未执行其中安装命令，也不代表项目已采用依赖或通过外部标准认证。

- [MCP安全最佳实践](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices)：本地服务启动是代码执行，需明确授权、最小权限；凭据受众和客户端授权不能靠token透传替代。本项目据此分离安装／启用与业务批准，并统一处理stdio代码。
- [Wasmtime安全模型](https://docs.wasmtime.dev/security.html)：Wasm对外作用通过明确提供的接口，WASI文件访问基于能力。本项目据此要求宿主接口最小化，但不将Wasmtime预选为所有插件的后端。
- [TUF规范](https://theupdateframework.github.io/specification/latest/#fetch-target)：更新目标的长度／摘要与版本元数据分别检查。本项目采用内容身份和受控更新原则；未审核本地导入不要求先接入签名仓库，签名与审核结论保持独立。本轮不实现TUF仓库／密钥体系。

本契约替代旧概念文档中宽泛的“未来插件注册一切”描述，具体扩展点逐项列出支持与权限；完整插件市场、依赖自动安装、任意跨平台backend和通用驱动平台仍非当前范围。下一轮按[实施checklist](../refactor/checklists/plugin-contract-2026-10-17.md)执行，未知机制不创建空框架。
