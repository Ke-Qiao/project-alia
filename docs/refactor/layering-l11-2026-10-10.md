## 所有者与实际清理

| 路径 | 本轮后的所有者 | 保持的原子边界 |
| --- | --- | --- |
| 规范 Response 与 assistant history | Interaction `ResponseCommitter` | Context 同事务复验、Response 状态/audit、chat_messages、session 更新时间一次提交 |
| Live admission | Companion `LiveRepository::admit` | source closure、policy、pending、预算与 grant、invitation Context、Response、pending admitted、期限检查一次提交；commit ACK 后才构造 Fresh permit |
| Shadow evaluate/replay | Companion `CompanionRepository` | 原来源授权与 shadow claims、operation/candidate、processed sources、erasure roots 一次提交 |
| Appraisal 来源授权 | Context `appraisal_source` | policy/account/privacy/relationship/source locks 与不可伪造的原 Context lease |
| Companion 来源与 grant | Companion `source`、`invitation` | CanonicalObservation、擦除引用、本域 private grant/预算完整性及当前 Companion 政策在调用者事务内验证 |
| invitation lease | Context `invitation` | Context 私有字段重签、证据合并、持久化与精确复验；不自行提交 |
| Delivery 事务参与 | Delivery repository 关联函数 | 仅使用显式传入的 DatabaseTransaction，无多余连接池实例或独立提交 |

`ConversationStore::commit_response` 和原实现删除。Interaction persistence 与 Companion runner 使用 Bootstrap 创建的同一个具体 `ResponseCommitter`；测试不再复制一个不完整的提交实现。它保留角色/name 校验、两秒 ACK timeout、稳定的 assistant message ID，以及重试时不重新创建已擦除历史的行为。普通 Conversation 存储仍通过原窄端口访问。

原 `context/companion.rs` 及其目录删除，无兼容转发入口。Context 不再解析 Companion private grant、预算收费或本域政策，也不拥有 CanonicalObservation 的定义与来源投影。ContextLease 的字段仍受模块私有权限保护；没有为了目录去耦而公开租约构造器。Context 的 CompanionAdmission 证据适配仍调用 Companion 的明确 helper，这是同一事务中验证跨域事实的必要依赖。

Delivery 的 `prepare_in_transaction`、`mark_generated_in_transaction` 改为不带 `self` 的关联函数，消除传入事务与实例连接池并存的歧义；内部 response 查询收窄为私有关联函数；无调用者的 `set_response_status_in_transaction` 删除。

## 锁顺序与不变量

来源授权保持 Context policy → active account → privacy epoch → relationship epoch → 原始 source closure 的顺序，之后才锁 Companion policy 和 grant/pending 等本域记录。邀请复验的首次 grant 读取仍不加锁，避免与“先锁来源再退役 grant”的擦除路径形成反向锁序。所有参与函数使用调用者的同一个事务。

保留默认 Shadow、当前 Enabled/quiet/paused 政策、来源时间戳与双 epoch、不可变 Context 证据、已有短准入期限和独立输出期限、不退费及容量策略。Shadow 不会获得输出 permit；已提交的 Existing 回执不会再执行 reserve/TTS。当前两类暂停、精确输出身份、工具迟到事实、关闭与热更新政策均不改变。

## 验证重点

- Live 的已有回归扩为三个故障点：Context INSERT、Response INSERT、pending admitted UPDATE。每个点证明前序写确已到达，并检查特定注入错误、六表基数与 pending 回滚，最后确认一次成功收费。
- Response 回归覆盖 assistant INSERT 与最后 session UPDATE 失败后的 Response/history/audit/Context 全部状态；并发同内容提交仍得到同一 ID。
- 新回归覆盖换一个 ResponseCommitter 实例后对已擦除 assistant history 的历史重试，不重建消息、不重复 audit。
- Interaction 使用真实 SQL 提交失败，验证不发布完成事件及 Memory capture；Linked fixtures 与缓存种子使用真实事务所有者。
- 架构守卫禁止旧 Context/Companion 路径、Conversation 重新拥有跨域提交、Context 重新拥有 Companion 业务政策/投影，并保留合法证据适配的正例。
