# 暂停纵向整合后的首轮任务 checklist

更新：2026-09-23。本表承接 [DU01—DU11](duplex-integration.md)，不是新一轮范围授权。以下六项仍属于已确认首轮目标或明确的后续技术评估；不得用软件测试通过代替真机出口。前端与通用 Embedded 适配继续按 [延期台账](../deferred.md) 处理。

当前 **0 / 6 完成**。六项规模不同，不把该数字换算成项目完成百分比。建议先完成不依赖外设的 R01；R02/R03/R05 的实际接入与验收需要台账 H01—H05 对应信息。

## R01 · Companion shadow、回放与受约束主动表达

- [ ] 核对已实现 Appraisal / Relationship / Affect / Regulation 的规范来源与剩余缺口，定义可回放的候选输入和决策证据。
- [ ] 先运行 shadow：记录候选、抑制原因和资源预算，不把未经许可的候选直接投递。
- [ ] 把准许的主动表达接入规范 Response / Context / Delivery，并遵守原 output owner、暂停、取消和来源失效。
- [ ] 验证用户正在说话、记忆删除、权限变化、重启和机会过期时不会陈旧投递或重复表达。
- [ ] 记录确定性回放结果、代码提交和真实输出边界，完成独立验收。

## R02 · AEC、音频时钟映射与双讲

- [ ] 固定 H02/H03 的 Pi 系统、采集/播放设备、采样格式及物理布局。
- [ ] 基于已有 native 播放参考与独立时钟契约接入实际 AEC，显式处理参考缺口与漂移。
- [ ] 实测同时播放/说话、附和、明确等待/继续、噪声、失联和重开；区分模型标签与声学质量。
- [ ] 记录端到端暂停/恢复延迟及设备配置；不能只报告模型推理耗时。

## R03 · D3 动作资产与执行器反馈

- [ ] 固定 H04 的控制板、执行器、反馈接口、机械限位和安全状态。
- [ ] 把签名动作资产、位置/速度限制及停止策略接入选定执行器。
- [ ] 验证迟到命令、断连、重启、限位和停止失败，保留真实执行与反馈证据。
- [ ] 分开报告接纳、提交、实际位置和完成，不把软件退休或网络 ACK 当作机构到位。

## R04 · CLI / REST 管理诊断与组件收敛

- [ ] 按全新安装用例核对配置、设备绑定、政策/记忆管理、执行确认、主动策略及诊断入口。
- [ ] 补齐首轮必要操作、当前协议/配置说明和错误反馈，保持不依赖 Web/iOS/Android。
- [ ] 对进入实际用例的 C01/C02 组件独立验证版本、权限、取消、资源与恢复行为，不因提案列名就整包引入。
- [ ] 完成命令/API 回归和开发者操作文档。

## R05 · Mac + Pi 整机验收

- [ ] 确认 H01—H05，锁定部署清单、模型地址/版本、密钥与全新数据库路径。
- [ ] 从干净环境执行安装、配对、启动、升级/恢复及关闭流程。
- [ ] 使用真实麦克风、声卡、扬声器与选定执行器，验证持续采集、物理停止和恢复听感。
- [ ] 至少 24 小时混合负载，覆盖断网、进程退出、设备重连与资源上界，保存可追溯报告。

## R06 · Server 平台与未来部署形态

- [ ] 对明确指定的其他 Server OS/CPU 建立构建与实际运行矩阵；当前 Linux ARM64 容器证据单独保留。
- [ ] 指定未来设备后，再评估 C04 的设备侧模型或同机多进程部署；当前不测试 Pi 5 承载 Easy-Turn。
- [ ] C05 的同进程组合、进程内传输与动态迁移分别按实际收益和故障边界评估，不因 Cargo feature 存在就宣称支持。

每个变更包继续使用三个 subagent 按独立文件/模块分工，Root 负责接口、组合验证和正常提交。每次收口写明：已完成条目、未完成条目、实际测试命令与结果、固定源码身份、资源状态、下一条可执行任务；发生额度暂停时保存四份 HANDOFF。
