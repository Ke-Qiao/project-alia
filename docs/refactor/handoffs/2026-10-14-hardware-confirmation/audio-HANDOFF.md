## 扬声器／功放链路候选

先确定功放输出取参考的兼容条件，再定型号与功率；目前保留下面两种，不额外扩张 I2S、蓝牙或新音频依赖。

1. **优先核对亚博配套 USB 声卡／功放／扬声器方案。** Pi 的最终混音流送入 USB 播放设备，功放驱动扬声器，同时按厂商认可的线束把功放输出送入 R1 参考口；R1 的 UAC 采集独立回到 Pi。亚博确有[“USB免驱声卡+扬声器”商品 526](https://www.yahboom.com/tbdetails/id/526)，可作为首个核对候选。不过公开商品页不足以证明它暴露兼容的参考接口，也没有核实其功放芯片、输出电平和用户将收到的版本，因此**仅凭同品牌不能宣告兼容**。应优先索取或读取 R1 附件中的厂商接线页与对应配套清单后确定。
2. **模块化 USB UAC DAC + 有明确资料的功放 + 匹配的被动扬声器。** 这保留选择音质、箱体和功率的余地；仍必须从最终功放输出按 R1 允许条件取得参考。只有确认 R1 的允许电平与取样方式后才挑具体功放及扬声器；目前不硬指定 PAM8403、MAX98357A 或其他型号。此项是由已确认参考拓扑提出的架构候选，不是现成兼容性结论。

上述两项都不把 DAC line-out 一分二当作已证明有效的 R1 参考方案。混音负责主回答、提示音、音量和取消的输出合成；AEC 负责利用实际播放参考消除回声。最终取参考的链路应覆盖实际扬声器发出的全部混音内容，但本轮没有据此修改 mixer、AEC、现有精确取消或清理逻辑。

此段复用 Root 已完成的真实只读证据，本分工未重复连机。原始记录为 `run/validation-20261014-hardware-confirmation/pi-inventory-configured.stdout.json` 和 `pi-access-inventory.json`（由 Root 统一归档）。

- Pi 5 Model B Rev 1.0、7.8 GiB，Ubuntu 24.04.4 LTS、aarch64、内核 `6.8.0-1065-raspi`。
- `lsusb` 仅显示五个 root hub；`/proc/asound/cards` 仅列两个 HDMI 卡。盘点本身仅证明当时没有枚举到 R1；用户随后确认 R1 尚未接入，解释了该结果。不存在已观察到的“接入后识别失败”，也不能据当前记录判断其接入后的驱动或供电状况。
- `arecord -l`、`aplay -l` 退出码为 0，但 stderr 报无声卡；`-L` 只有 null PCM。**不能把退出码 0 计为音频就绪，也不能把这里的无卡提示解释为内核没有任何声卡。**
- 补充权限证据显示 `/dev/snd` 音频节点为 `root:audio`、0660，当前 `ke-qiao` 账户不可读写；权限会影响用户态枚举／访问。当前尚未修改用户组、ACL 或 udev，也未打开 PCM 录放音。

## 下一 R02 的有界只读顺序

1. 按已确认的 **R1 → USB → Pi 5** 目标，核对实物主板／麦阵版本、固件标识和配套线束，使用用户或设备提供的信息对应官方文档。连接主机与接口无需重问；具体线序与电气条件不能按照片颜色或相似插头推断。
2. 等 R1 实际接入 Pi 5 后，重新记录 `lsusb`、`lsusb -t`、`/proc/asound/cards`、`/proc/asound/pcm`、`arecord -l/-L` 与 `aplay -l/-L`，同时保留 exit code 和 stderr。
3. 对明确发现的目标设备读取 sysfs/udev 的 VID/PID、产品名、序列号和物理路径，读取对应 `/proc/asound/cardN/stream*` 中的 USB capture/playback 能力；稳定标识优先于“第一张声卡”或固定 card 数字。记录 R1 capture 与独立播放 DAC 的对应关系。
4. 读取目标 `/dev/snd` 节点的属主、权限和 ACL，区分“硬件未枚举”与“当前服务账户不可访问”。先形成所需最小访问范围，再由 Root 处理权限步骤；本轮不自动改组／ACL。
5. 仅在目标卡与权限已明确时，按需读取 ALSA controls/contents，不执行设置命令。固件版本查询只使用已公开、明确无写入的查询协议；不盲开 UART、不猜波特率、不刷写。
6. 把这些只读结果与参考信号电气资料、实际功放／扬声器版本合并成 R02 录放音前置包。`arecord` 实际采集、`aplay`/`speaker-test`、可能打开 PCM 的能力探测以及 AEC 双讲测试留在后续明确的实机验证窗口。

本轮已收口资料搜索；未做声学测量，也未确认功放或扬声器采购型号。恢复工作的首个缺口是设备实物／枚举与运行账户权限，其后才是参考电气匹配；不能将现有软件 mixer 测试或其他六麦的示例当作 R1 AEC 验收。
