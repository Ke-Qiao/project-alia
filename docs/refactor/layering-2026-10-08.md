# Memory / Interaction 目录与依赖分层

日期：2026-10-08。起点 `adb28c1`，分支 `codex/architecture-refactor`。
执行范围和数字进度见 [checklist](checklists/layering-2026-10-08.md)。

## 本轮解决的问题

旧实现已经具有来源身份、Context、隐私撤销和规范交付等新契约，但目录与依赖仍有旧架构残留：Memory 的真实存储在 `providers/memory`，Memory 类型和带默认业务实现的 trait 位于 `providers/adapter.rs`；Channel 下的 Pipeline 同时负责输入监督、生成、缓存、表达和提交；`module` 又混合装配、聚合服务容器与生命周期。

本轮复用经过验证的存储与交付实现，改变职责归属、依赖和重复流程。没有新增外部依赖、进程、Cargo feature、模型、数据迁移或硬件动作。

| 原位置 / 责任 | 当前归属与改变 |
| --- | --- |
| `providers/memory`、`MemoryBackend`、`AliaMemory`、`NoopMemory` | `modules/memory::MemoryService` 固定核心服务；原真实实现的 25 项操作全部成为具体方法，删除 provider 目录、MemoryBackend 抽象、单实现工厂和 no-op Memory；基线已禁止配置替换 Memory。 |
| `providers/adapter.rs` 的 Memory 类型 | `modules/memory` 拥有类型、序列化和纯内存投影；这些类型不依赖 SeaORM、Tonic 或具体模型 SDK。 |
| 顶层 `memory_policy.rs` | `modules/memory/policy.rs`；保留现行敏感信息、合并和提示策略。 |
| Pipeline 的 `memory_capture` | `modules/memory/capture.rs`；使用 Memory 自己的 `CaptureTurn` 输入与明确的 Context / Memory / LLM 参数，不接收整个运行时 Registry 或 Interaction 的持久化对象。 |
| `channels/pipeline` | `modules/interaction`；有界入站监督与具体轮次用例分开，生成按上下文准备、缓存、路由、模型执行与完成流程组织。 |
| 全局 `ModuleRegistry` 作为轮次参数 | Bootstrap 明确提供 `InteractionServices`，仅含实际使用的 17 项服务；不暴露 scheduler、STT、Companion、扩展列表或进程清理 owner。 |
| `module/{builder,factory,registry}` | `bootstrap`；选择具体适配器、构建服务图、保留启动和关闭所有权。Easy-Turn 的具体构造也归 Bootstrap。 |
| `module/{lifecycle,background}` | `modules/platform`；保留启动回滚、任务排空、超时后继续拥有清理任务等行为。 |

旧目录和公开路径直接删除，调用者与测试迁到当前归属；不提供同名 alias、兼容门面、双写或双执行路径。历史验证文档保留原样，不把旧记录批量改写为新路径。

## 行为与依赖边界

Memory 关闭召回/采集时，仍可执行合法管理与删除。生产数据库初始化失败不回落到内存；内存服务仍只作为明确测试 fixture。Context、隐私 epoch、来源失效、Memory guarded transaction 与 embedding profile/projection 条件保留。

Interaction 的精确缓存和语义缓存共用完成出口。模型/Skill 路由复用实际执行阶段；缓存命中仍不重生成，流式文本/音频仍保留原 producer 和 Response 身份。取消、临时避让、明确暂停、工具派发后结果入账及原有持久政策保持原职责。

缓存退出的独立审查发现：新提前退出原本漏记取消终态。新增阻塞缓存回归已在修复前稳定失败（终端事件数 `0`，预期 `1`）；修复在退出前记录原始用户来源和实际取消阶段，同时覆盖精确和语义缓存，仍不生成 Response、assistant history、缓存写入或 Memory capture。修复后的通过证据见最终验证记录。

Bootstrap 为 Interaction 克隆原服务的 `Arc`，不新建第二套状态 owner。生命周期迁移保留原 init/start 和 shutdown phase 顺序；同时移除同一个 `memory_capture_llm` 重复应用设置的调用。

架构守卫为 `python3 scripts/check-server-boundaries.py`，负例检查用 `--self-test`。它检查本轮删除的旧路径、Memory 契约位置、Memory/Interaction 不依赖聚合 Registry/装配，以及 capture 输入和 Memory 纯域类型的依赖方向。它不是完整 Rust 语义分析，也不能代替行为测试。
