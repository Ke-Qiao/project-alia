# Embedded 运行时装配与退出

2026-09-08 实施包。面向 Pi 5，同时保持库可由宿主调用；不因此宣称已完成其他嵌入硬件适配。

`EmbeddedBuilder::build` 先绑定 gRPC 端口，再初始化模块。已选中的模块初始化或启动失败会返回错误，并按依赖逆序清理已初始化对象；不会因失败静默换成 Noop。明确配置的禁用能力或 Noop 仍可使用。

`[device_runtime]` 配置监听地址、SQLite 状态路径、插件目录、整体关闭预算和 gRPC 排空预算。相对路径相对于配置目录解析。`listen_addr` 可以使用端口 0：`node.local_addr()` 和 `node.config` 包含实际地址，mDNS 广告使用实际端口；`node.requested_config` 保留请求值，设置持久化不会意外把随机端口固定下来。独立实例必须使用各自的状态目录、身份文件及端口。

`EmbeddedNode::run` 不安装全局日志、信号处理器或额外 Tokio runtime。可独立运行，也可由未来组合入口与 Server 库共同装配。当前没有实现进程内媒体传输，仍使用正常的认证协议。

正常退出包含停止接收新请求、有限时间排空 gRPC、关闭仍存活的 HTTP/2 连接，以及等待模块停止。Tonic 内部连接任务不会仅因丢弃 server future 而自动消失，因此节点另外拥有 socket 取消与活动连接计数。长期没有 EOF 的旧 Upload 流也必须被关闭。

清理只有一个所有者。部分原生模块停止时会同步 join OS 线程，因此清理放在一个受管理的 blocking worker 上，避免卡住单线程 Tokio 宿主。超过关闭预算会返回 `ShutdownIncomplete`，其中包含尚未完成的模块名和可继续等待的 `ShutdownHandle`；超时不会被记录为硬件已经停止。调用方可提前取得 `node.shutdown_handle()`，在 run future 被取消后继续等待真实清理结果。

可执行入口负责 SIGINT/SIGTERM，并显式管理 Tokio runtime 的最终关闭期限。这能限制进程等待时间，但不能强行中断一个卡住的原生线程；库宿主应处理返回的失败与未完成句柄。真正的机构到位、声学停止仍需要硬件证据。

运动模块在尚未尝试激活时的回滚不会发送回中动作。实际激活尝试后，启动或复位失败会明确上报。插件清理会尝试停止所有活动插件，收集各自错误，等待成功请求对应的进程退出，避免第一个错误阻止其余清理。

本包验证：`cargo test -p alia-embedded --no-default-features --locked`，122 项通过，0 失败。其中运行时 11 项验证占用端口、实例隔离、构建取消/abort、实际 gRPC 长期 Upload、单线程宿主、超时后继续等待、以及未激活运动模块的回滚。配置集成测试 16 项通过。平台构建结果另记入构建记录；这些测试使用替身硬件，不代表实际 Pi 音频、执行器或 AEC 已验收。
