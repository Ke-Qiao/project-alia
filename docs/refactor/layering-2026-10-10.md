# L10：显式初始化依赖与全局参数包退役

日期：2026-10-10；基线 `cb19992`，分支 `codex/architecture-refactor`。承接 L09 已完成的核心归属迁移，本轮只完成初始化依赖收窄。执行状态见 [checklist](checklists/l10-2026-10-10.md)，交接见 [四份 HANDOFF](handoffs/2026-10-10/README.md)。本轮验收已完成，源码和最终证据见下表。

## 架构变化

原 `ModuleContext` 把整个 ServerConfig、数据库、各领域服务、模型、插件存储、注册表和运行控制交给所有模块。模块只使用少数字段，签名却无法表明真实依赖，测试也必须伪造无关字段。本轮删除这个结构和 plugin context 辅助入口，不保留别名或兼容转发。

组件构造时显式绑定必要配置与依赖；`ModuleLifecycle::init(&mut self)` 无参数，只负责已绑定组件的初始化。Bootstrap 负责创建、投影配置和连接服务图，领域组件不再接收整个 ServerConfig。真实独立使用的内存 Store、手工工具目录、纯 CLI 与 transport fixtures 仍保留其实际用途。

| 组件 | 明确绑定的依赖 | 受 cleanup 保护的初始化动作 |
| --- | --- | --- |
| Conversation / Cache | 数据库；Cache 另有父取消令牌 | 原连接准入、到期缓存清理 |
| Persona / Skills | 数据库；Skills 另有 ArtifactRegistry 和已解析资源目录 | 模板读取、种子及 Markdown 同步、索引加载 |
| Memory | 数据库、Embedding、MemorySection、完整 ContextPolicy、取消令牌 | 实际 embedding profile 注册、持久政策初始化、运行状态发布、健康探测 |
| Insights | 自身 InsightsSection、数据库、事件总线、取消令牌及实际消费的模型/Memory/Cache/Scheduler/Conditions | 启动状态绑定；后台 worker 仍由 start/stop 管理 |
| LLM / Embedding / STT / TTS | 对应 profile、provider section；TTS 另有 voice 与 expression profiles | 原配置告警；TTS 远端权重配置保留在 init |
| Scheduler / Rules | 自身配置、数据库、事件总线、取消令牌、Condition/ActionRegistry | 原 SQL 恢复；成功后才标记已初始化 |
| Builtin tools | 数据库、事件总线、ArtifactRegistry、Memory、Scheduler；实例上注册 Sensor executors | 废弃目录清理、工具注册与 SQL 同步 |
| CLI / Embedded Channel | CLI 的会话存储、数据库、取消令牌；Embedded 的数据库、Sensors、ServerSection、keypair path | 原身份恢复、Body 状态恢复、密钥读取、sensor provider 注册 |
| Home Assistant | 自身配置、PluginStorageService、ToolRegistry | 原配置验证、manifest scoped storage、脱敏配置存储和执行器注册 |

`InsightDependencies`、`EmbeddedRuntimeDependencies` 和私有 `MemoryInitialization` 仅包含各自组件的实际启动输入，不传递给其他模块，也不提供服务查找。Memory 的完整 ContextPolicy 由 Bootstrap 在持久政策加载后投影，保留 Cache、Appraisal 和 Conversation 政策；没有用单独 MemorySection 替代。

`create_scheduler`、`create_rule_engine`、`create_tools_with_sensors` 三个固定工厂删除，Builder 直接构造。真实外部适配器与 Channel 仍由工厂选择类型，工厂只投影对应配置。动态 Channel API 与初次启动共用新构造契约。

## 生命周期和失败语义

RuntimeCleanup 先登记 Initializing slot，再调用 init。失败、取消或 panic 仍保留待停止实例；Arc 转移无中间 await，cleanup phase 与 channel ownership transfer 保持。SQL、工具目录注册、keypair 读取、TTS 远端权重设置没有移到不受 rollback 管理的构造阶段。固定只读依赖不再额外套 Mutex，运行中的可变状态和任务锁继续保留。

独立审查发现 Insights 的 feature 拒绝时机因依赖装配后移而延后，已用共享 `check_available` 恢复原早期检查。新增无默认 feature 回归用 TTS 生命周期 Probe 证明错误发生于 TTS init 前；构造函数本身也继续检查，避免其他调用者绕过准入。

测试 Probe 不再靠全局参数包取得数据库。成功构建的关闭测试显式绑定实际 runtime pool，继续验证 stop 内 SELECT 1。失败启动无法取得 runtime 时，通过唯一 application_name 和参数化 pg_stat_activity 查询确认 rollback 等待期间连接存在、完成后有界归零。此查询证明连接存续和释放；池仍能执行查询由成功构建的 native-stop 测试独立覆盖。

## 防回退与验收范围

架构守卫禁止 ModuleContext 声明、引用和别名，生命周期 init 不允许新增参数，20 个已迁移具体实现文件不能重新接收 ServerConfig；禁止恢复三个固定工厂。Bootstrap 配置投影、现有 Context/Appraisal policy 转换与 provider contract 的配置转换仍合法。守卫基于明确路径与正则的受限静态检查，不声称是完整语义依赖分析。

除既有完整回归外，本轮增加 Memory 初始化失败不发布运行时依赖、TTS 构造不设置远端权重且 init 失败仍按原策略降级、无 Insights feature 提前拒绝三个行为检查。三个 agent 完成互斥文件实施与静态对照，Root 独占 Cargo / PostgreSQL 和容器验证。

本轮不修改默认 Shadow、政策、双 epoch、Context 授权与原子提交、临时避让/明确暂停、Response/Delivery 身份和 dispatched tool 迟到事实。不新增依赖、feature、平台或硬件动作。用户 5433 不访问。
