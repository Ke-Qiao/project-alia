## 已有实现与实际缺口

三个 HTTP 写入口已有 skill、preferred bindings、artifact/dependency 的同一数据库事务，错误与依赖检查可复用。缺口是提交后的三个 reload TODO：数据库已更新而运行中的 match、list、resolve 仍旧。旧 loader 又会先读取 skill 行，再取得共享索引写锁并清空；其后的逐条 SQL 失败可留下空或半成品索引，并发旧 reload 还可能覆盖新内容。

单独在提交后补 reload 不能解决上述问题：reload 或构造响应失败时，数据库已经提交，HTTP 却报失败。当前实现把准备、提交和发布统一交给 Interaction 的 `SkillRegistry`，HTTP 保留请求及领域数据变更。没有新增缓存体系、依赖、feature 或数据库迁移。

## 最终事务与生命周期

1. `SkillChange` 取得 Registry 变更 gate，检查是否停止，开启 Repeatable Read 事务；第一条非事务控制 SQL 是 `LOCK TABLE skills IN SHARE ROW EXCLUSIVE MODE`。
2. HTTP 在同一事务中读取旧值、变更 skill / bindings / artifact / dependencies，并为 create/update 构造完整响应。并发 update 不再提前读同一旧值。
3. Registry 使用三个完整查询读取 enabled skills、bindings、enabled tools，在临时 map 构建完整快照。失败发生在 COMMIT 前，原索引保持，事务退出回滚。
4. 取得索引写锁后，把提交交给已有 `RuntimeTasks`。worker 持有事务、变更 gate 和索引锁，先将索引置为不可用，再执行 COMMIT。成功后无 await 一次发布完整快照。HTTP 只有收到 worker 成功结果才返回已准备的响应。
5. 等待请求取消不会丢弃已交接的 worker。COMMIT 错误仍返回原 `DbErr` 分类；worker 经过新的表锁屏障重读实际数据库。重建成功则发布实际内容，失败维持不可用，match/list/resolve 返回错误且健康状态 degraded，后续成功 reload 可恢复。
6. 显式 reload 使用同一 gate 和完整快照构建；构建期间旧索引仍可读，完成后一次替换。stop 等待变更 gate，关闭新变更与 reload 准入，再 close/wait RuntimeTasks，确保已交接的任务完全结束。

表锁的目的包括处理 COMMIT 回执不确定：原数据库 backend 可能仍在完成提交，新连接不能先读到旧状态便声称恢复完成。恢复过程先等冲突表锁释放，再建立 RR 查询快照。本轮隔离 PostgreSQL 探针确认此顺序能够读取等待期间完成的 writer 新值；这不是实际网络 COMMIT ACK 丢失的端到端注入测试。

同步承诺针对当前进程 Registry 的成功 HTTP CRUD。多进程或外部 SQL 不会主动广播索引失效；仍需显式 reload。表锁保持普通读可用，并串行化管理写入；没有新增锁等待期限或线上性能承诺。HTTP list/get 继续读数据库，不变成跨查询原子列表接口。

## 干净清理与政策边界

- 删除全仓无调用的 Registry CRUD/get_by_name/list_all_db/plugin 注册卸载 facade 及 `PluginSkillDefinition`；实际 builtin/file 初始化保留，无兼容转发层。
- 边界守卫阻止旧 facade 与 plugin 符号复活、阻止 Skills HTTP 再直接持有 `TransactionTrait`，并补正反自测。
- 默认 Shadow、现有账号认证、全局工具可见性和 Execution 批准代码均未改变。preferred tools 仍是排序偏好，不授予执行权限。
- 保留 unknown preferred tool 的校验与事务回滚、禁用工具过滤、依赖阻止删除、404 和原数据库/内部错误分类。请求数组元素和 nullable 字段的既有接受语义未扩张。
- 内存列表供 prompt 使用、resolve 供 generation 使用，随新索引发布更新。静态 classifier 自动发现新技能属于独立后续项，不能将本轮成果表述为任意新 skill 自动进入路由候选。

## 回归覆盖与候选失败

新增 1 项错误映射单测、4 项真实 PostgreSQL Registry 测试、3 项真实 HTTP runtime 测试。覆盖 CRUD 后立即可读、禁用/启用/删除、授权/404、preferred filtering、未知工具和依赖失败回滚；响应或快照读取故障不破坏旧索引；实际数据库锁等待下的旧索引读取与新快照顺序；并发 update 保留双方字段；COMMIT 等待者取消、关闭等待与拒绝新准入；真实延迟约束导致 COMMIT 失败、重建失败停用索引及 reload 恢复。

工具政策测试具体核对 `schedule_task` 的目录/确认字段、preferred skill 不扩权、`confirmed=true` 仍提出待批准操作、其他用户不能批准、未产生计划任务及所有者取消。数据库中的 disabled fixture 不会成为 executor。这是具体路径证据，不声称穷尽所有工具与所有调度。

V1 的 HTTP 3/3 通过；macOS 与 Linux 定向 lib 均 7 通过 / 1 失败，真实失败是测试错误要求连接池 close 第一次 poll 必须 Pending。V2 只修改 `registry_tests.rs`：允许 Ready/Pending，直接断言 SQLx pool.is_closed，避免重复 poll 已完成 future，并在测试替换依赖前有界等待 owned worker 释放 Registry。原 COMMIT、DbErr、fail-closed、健康与 reload 断言全部保留。两份 643 输入 manifest、差异及原失败日志分别归档，不用复跑覆盖原失败。
