# /health 聚合与探测所有权清理

本轮承接 `d27490f`，使用三个 subagent 分别处理 Registry 聚合、Provider/Router 和真实 HTTP 回归；Root 负责 Builder 所有权、整合验证、证据与提交。保持既有 API、默认 probe=false、Shadow、工具可见性和 Execution 批准。

## 审计结论与改动

原实现逐项 await ModuleRegistry 检查，整体耗时可累加。Router 又探测一次 minor；Builder 为相同 profile 的多个角色重复创建实例，因此仅在聚合处按指针去重不足以消除真实重复探测。OpenAI 已有独立 5 秒期限、配置快照与安全诊断，直接复用。Gemini 原持配置读锁跨网络等待且无独立期限，并把原始传输错误暴露给健康响应。

| 边界 | 当前实现 |
| --- | --- |
| API | 公开 `GET /health`、HTTP 200、`status/version/modules` 与原模块 keys 保持；可选 LLM role 仍按实际存在与否返回。setup 阶段 `/health` 独立且未改动。 |
| 总预算 | 每轮从开始计时 6 秒，排队项共用同一绝对期限；已完成结果保留，仅未完成项降级。 |
| 并发 | 单 Registry 同时只接纳一轮，最多 8 个实际检查；其它请求立即逐项 busy 降级，不等待、不缓存、不启动巡检。 |
| 实例 | 配置相同 profile 的多个 LLM 角色共用 Arc，初始化、启动和停止各一次，每次设置更新只应用一次；显式注入的独立对象保持独立，即使名称或配置角色相同。 |
| 聚合去重 | 实际对象相同只检查一次，再把结果映射回各角色；名称相同不会合并不同实例。 |
| Router | 仅检查当前模式与 minor 绑定，删除递归 Provider probe；模型健康由 `llm.*` 报告。 |
| Provider | OpenAI 原行为保持；Gemini 使用配置快照、5 秒 GET 期限、固定安全错误类别，不输出请求 URL、key 或响应体。 |
| 生命周期 | stop token 中断在途聚合，之后不准入新探测；超时、停止及调用者 drop 释放借用 future 与 gate，没有脱离请求的后台检查。 |
| 故障 | 单项 panic 转为固定 `unhealthy`；其他检查继续。共享 profile 的失败 init 仍归原 rollback owner。 |

busy=`health check already in progress`；整体超时=`health check timed out after 6s`；stop=`server is stopping`；panic=`health check panicked`。三个前者为 degraded，后者为 unhealthy；上层仍沿用原最坏状态汇总。没有添加深度诊断端点、HTTP probe 开关、配置或结果缓存。已发出的探测使用开始时快照，后续空闲请求重新检查当前配置。

现有三个网络 LLM Provider 的请求历史、解码器和工具缓冲均在请求内构建，实例仅保存 Client/profile/配置；相同 profile 共享不共享会话内容。一般生成流程中的既有读锁行为未改动，不将健康检查的锁修复扩大描述为全生成流程无锁。

## 回归与证据

Registry 五项确定性测试验证同实例/同名边界、已完成结果、精确 8 项上限与原始期限、busy/drop、stop 和 panic。Builder 一项覆盖共享初始化、独立 override 与失败 rollback。Router 一项验证不再调用 Provider health；Gemini 五项本地网络回归覆盖默认不连接、HTTP 状态/脱敏、实际 5 秒超时与设置更新、取消 socket 释放及 Unix 拒绝连接。

真实 runtime HTTP 三项覆盖四角色同 profile 单 GET、默认关闭零连接、四个重叠请求不排队、后续请求新鲜、两个独立同名检查的 6 秒预算及 drop，以及停机时 HTTP 完成与 runtime join。使用原隔离 PostgreSQL fixture，未更改原测试期限或默认并行度。
