# Affective Companionship and Smart Home Hub Device

> 2026-11-08 状态更新：本文描述清理前的系统。旧前端现已删除，WebView、Swift 和 Kotlin 三端尚未实现，计划见 [README](../README.md#planned-frontends)。

## 1. PPT 第 1 页：背景与目标

### 项目名称

**Affective Companionship and Smart Home Hub Device**

中文可表述为：**情感陪伴型智能家居中枢设备**。

### 项目背景

随着单人居住、远程学习和居家办公场景增加，传统智能音箱或智能家居入口虽然可以完成语音控制，但大多停留在“命令-响应”的工具层面。它们通常缺少长期记忆、人格连续性和可感知的陪伴表达，用户每次交互都像从零开始。

本项目试图把智能语音助手、智能家居控制和具身情感陪伴结合起来，让设备不只是一个被动执行命令的终端，而是一个能记住用户偏好、理解当前场景、通过语音与动作做出反馈的居家伙伴。

### 核心痛点

项目要解决的核心痛点是：

**单人居家场景中聊天互动缺失，以及现有智能家居系统缺少长期记忆和情感连续性。**

具体表现包括：

- 普通智能家居系统只处理即时指令，无法形成持续的用户理解。
- 语音助手缺少具身反馈，互动更像设备控制面板，不像陪伴对象。
- 多数系统没有把语音、记忆、情绪表达、动作执行和家居控制统一到一个可扩展架构中。
- 家庭场景对响应延迟、打断、隐私、安全和设备可靠性要求较高，不能只依赖云端大模型直接控制硬件。

### 项目目标

本项目设定的目标是构建一个**二次元可动胸像形态的智能陪伴设备**，同时满足以下能力：

- **智能语音交互**：支持唤醒词、语音识别、LLM 对话、语音合成和连续对话。
- **智能家居控制**：通过工具、传感器、规则和调度系统连接家庭设备与自动化场景。
- **情感陪伴**：通过记忆系统、关系状态、表达规划和语音风格，形成更连续的陪伴体验。
- **个人助手**：支持任务执行、信息查询、提醒、设备状态读取和用户偏好管理。
- **可动具身表达**：通过脖子绳驱机械结构和动作控制，让角色能点头、看向用户、低头等，增强真实感。

可用于 PPT 的一句话目标：

> 设计一个具有长期记忆、自然语音交互、智能家居控制和可动情感表达能力的二次元桌面胸像，使智能家居入口从“指令工具”升级为“有陪伴感的个人助手”。

## 2. PPT 第 2 页：核心概念设计

### 总体方案

项目采用“**服务器大脑 + 嵌入式边缘节点 + 前端配置应用 + 可动胸像硬件**”的分层架构。

```text
用户语音 / 传感器 / 前端设置
        ↓
嵌入式边缘节点：唤醒词、VAD、音频采集、播放、动作执行、传感器
        ↓ gRPC
服务器：STT、LLM、记忆、技能、工具、自动化、表达规划、TTS
        ↓
语音回复 + 动作计划 + 家居控制结果
        ↓
可动二次元胸像：说话、看向用户、点头、低头、陪伴反馈
```

这种设计把实时性要求高的任务放在本地边缘端，把推理、记忆、工具调用和多模块编排放在服务器端，前端负责设置、设备管理和可视化检查。

### 主力设计方案

| 模块 | 采用方案 | 作用 |
| --- | --- | --- |
| 机械结构 | 二次元可动胸像，脖子采用绳驱机构 | 让角色具有低成本、柔和、拟人的头颈动作 |
| 运动控制 | RBF 函数矩阵映射 + 示教保存姿态 | 不依赖复杂逆运动学，通过样本姿态映射到舵机角度 |
| 电子控制 | Raspberry Pi/Linux 边缘节点 + PCA9685 舵机控制 + 麦克风/扬声器/传感器 | 负责音频、动作、传感器和设备连接 |
| 软件系统 | Rust server + Rust embedded + Expo/React Native frontend | 形成稳定、可扩展、可观测的 AI 助手系统 |
| AI 语音链路 | wake word + VAD + STT + LLM + TTS + streaming playback | 支持自然语音交互、连续对话和打断 |
| 情感表达 | Appraisal → Affect/Social/Resource → Regulation → Expression Plan → Adapter | 将情绪判断、表达意图和设备执行解耦，避免 LLM 直接控制硬件 |
| 家居能力 | tools、skills、sensors、rules、scheduler | 支持设备读取、控制、自动化和场景联动 |
| 记忆能力 | Alia 内置记忆策略和存储 | 只保存稳定事实、偏好、目标和关系上下文，避免无控制地记录所有对话 |

## 3. PPT 第 3 页：详细设计与工程优势

### 机械结构：脖子绳驱可动胸像

机械结构选择脖子绳驱方案，而不是传统刚性连杆或复杂机械臂，主要原因是：

- **拟人表达更自然**：头颈小幅动作、点头、低头、看向用户等动作适合陪伴型角色。
- **结构紧凑**：胸像内部空间有限，绳驱可以把执行机构布置得更灵活。
- **安全性更好**：动作幅度和力矩可控，适合桌面近距离交互。
- **成本和可制造性较优**：可使用多路舵机和 PCA9685 进行控制，适合原型迭代。

当前嵌入式配置中运动模块支持 8 路舵机、PCA9685、I2C、动作帧率、中心角、面部跟随角度范围和平滑参数，说明机械控制已经按可部署设备来设计，而不是一次性演示脚本。

### 控制算法：RBF 函数矩阵映射

脖子运动控制采用 **RBF 函数矩阵计算**。输入是目标头颈旋转姿态，输出是多路舵机角度。

核心优势：

- **不需要逆运动学建模**：绳驱机构的受力、摩擦、弹性和装配误差很难精确建模，RBF 可以绕开复杂的解析逆解。
- **通过示教保存位置**：只需要采集若干典型姿态和对应舵机角度，就能形成映射矩阵。
- **适合非线性结构**：绳驱脖子的实际运动不是简单线性关系，RBF 的高斯基函数能表达平滑的非线性映射。
- **迭代成本低**：机械结构调整后，可以重新示教关键姿态，而不是重推整套运动学公式。
- **运行时计算轻量**：嵌入式端只需要计算 RBF 权重和矩阵加权求和，适合实时动作控制。

可用于 PPT 的算法描述：

```text
目标头颈姿态 [pitch, yaw, roll]
        ↓
与示教姿态计算 Gaussian RBF 权重
        ↓
RBF 权重 × 舵机映射矩阵
        ↓
输出 8 路舵机角度
        ↓
限幅、平滑、轨迹插值后发送到 PCA9685
```

### 软件系统：模块化 AI 助手架构

软件方案可以填为：

**Rust 高可靠服务器 + Rust 嵌入式边缘运行时 + Expo/React Native 前端 + 可替换模型服务适配器。**

其中：

- `alia-server` 负责 AI 编排、用户状态、记忆、工具调用、技能路由、自动化规则、TTS/STT/LLM 适配和数据持久化。
- `alia-embedded` 负责本地音频 I/O、唤醒词、VAD、直接反馈、播放打断、传感器、设备绑定和动作执行。
- `alia-frontend` 负责用户设置、设备管理、会话、插件、传感器和运行状态观察。
- 模型服务通过 provider adapter 接入，可替换 OpenAI-compatible、Anthropic、Gemini、whisper.cpp、GPT-SoVITS 等后端。

### 情感表达设计

本项目的情感表达不是简单给 TTS 加一个 emotion 标签，而是使用分层表达运行时：

```text
用户输入
  → Appraisal 事件理解
  → Affect / Social / Resource 状态
  → Regulation 表达调节
  → Expression Intent Planner
  → Expression Realizer
  → Safety Policy
  → TTS / Motion / Face / Light 等 Adapter
```

这种设计体现了工程思维：

- LLM 只参与高层语义，不直接控制电机。
- 情感状态和外在表达分离，避免“开心地说严肃内容”。
- 动作执行前进行能力协商和安全限幅。
- 当动作硬件不可用时，可以自动降级为 speech-only。
- 表达过程可追踪、可回放，便于调试为什么某一轮表现不自然。

### 智能家居与个人助手能力

项目将 smart home 能力抽象为工具、技能、传感器和自动化规则：

- **Tools** 是可执行动作，例如读取传感器、控制设备、存储记忆。
- **Skills** 是认知上下文，例如智能家居控制、记忆型对话、信息查询。
- **Sensors** 通过统一注册表暴露给工具、自动化和前端。
- **Rules / Scheduler** 支持事件触发、定时任务、条件轮询和工具调用。

这使得系统不仅能聊天，还能真正成为家庭设备的中枢。

## 4. 项目特点与优势总结

### 1. 具身陪伴，而不是普通语音盒子

项目用二次元可动胸像承载助手人格，通过语音、动作和表情意图形成具身反馈。用户看到的是一个会回应、会看向自己、会用小动作表达态度的角色，而不是一个只会播报的扬声器。

### 2. 记忆驱动的长期陪伴

系统支持用户记忆、偏好、关系状态和会话历史。它不是每次都从空白开始，而是能围绕用户习惯、稳定偏好和长期互动关系调整回答与表达。

### 3. RBF 示教控制适合绳驱机构

脖子绳驱机构存在复杂非线性，传统逆运动学建模困难。RBF 映射通过示教样本直接建立“姿态到舵机角度”的关系，降低机械建模难度，提高调试效率。

### 4. 边缘节点保证交互实时性

唤醒词、VAD、直接反馈、播放打断和动作执行都在本地完成。这样即使服务器响应较慢，用户也能先获得即时反馈；当用户打断助手说话时，设备也能立刻停止播放。

### 5. 服务器负责复杂智能，边缘端负责实时硬件

服务器处理 LLM、记忆、工具、自动化和表达规划；嵌入式端处理音频、舵机、传感器和播放。这种职责划分让系统既有大模型能力，又不会把实时硬件控制暴露给不稳定的生成式模型。

### 6. 模块化 provider 设计，便于替换模型

STT、LLM、TTS、embedding、memory 都通过 provider adapter 接入。未来可以根据成本、性能、隐私或部署环境切换模型服务，不需要重写核心流程。

### 7. 安全可控的情感表达

系统有表达调节、动作 allowlist、强度限制、时长限制、夜间模式、低电量/热状态降级等机制。设备可以表现情感，但不会无约束地夸张运动。

### 8. 面向真实家居场景的可靠性

架构强调 degrade instead of crashing：某个模型服务、传感器或动作硬件不可用时，系统尽量降级而不是整体崩溃。这对家居设备比一次性 demo 更重要。
